# Editorial V2.1 and object intelligence review

This change affects the existing reviewed Editorial workflow only when Editorial Knowledge V2 is enabled. It preserves `qualityVersion: 3`, the public Editorial API, the five weighted dimensions and their thresholds, the four-call bound, fallback, permissions and inference budgets. The knowledge version changes to `curio-editorial-knowledge-v2.1`, invalidating prior V2 cache keys; existing cached content must still pass current publication checks.

## Root cause and evaluation

The V1 Chief instruction banned paraphrases of owner-supplied brand/product descriptions and prescribed `appears ...-like` wording. V2 added broad guidance but retained those conflicting commands. The rubric rewarded visual observations and connections without explicitly asking whether a feature used its brand/product evidence meaningfully. The source loader also silently let the last of two product links win when source IDs collided. V2.1 changes those three points, without weakening the technical gate or the independent Reviewer.

The authentic *Intervals of Stillness* text in `tests/fixtures/intervals-of-stillness-live.json` is the reproducible non-billable baseline. Its three narratives repeat light/shadow/space terms and its questions chiefly explore composition. The repository does not contain the complete live text of *Rituals in Light and Interval*, its exact cited source IDs, or its Reviewer result; do not infer those from the earlier fixture. No new Meta output was generated for this PR.

For review, compare real before/after editions on: (1) each feature's distinct supported idea, (2) useful use of cited brand/product context, (3) a specific thematic bridge between adjacent assets, (4) natural language without internal observation terms, and (5) zero unsupported factual claims. A pass requires all five, with any hard factual failure requiring revision or fallback regardless of score. The local prompt tests establish instruction propagation; they are not proof of improved live prose. A controlled live edition after approval is needed for that judgment.

## SAM status and minimum later scope

`worker/decoder.ts` implements a default-off, operator-only SAM 3.1 request for one catalog detail and exact approved image. Private R2 image bytes are supported. `worker/sam-client.ts` parses bounded SSE and normalizes model boxes to image-relative coordinates. `shared/decoder.ts` marks model boxes `sam_detection` and `model_estimate_not_identity`; authored illustration boxes are `authored_demo`. The Decoder returns its result but does not save it to `object_regions`. A separate authenticated catalog annotation store can persist regions, but it is not wired into this live Decoder response. The parser consumes box records; the public object contract does not expose a persisted mask. `shared/object-localization.ts` can combine exact-version captures for offline review, but this is not evidence of a Production run.

Content Studio creates `discoverableObjects` from owner metadata labels with `grounding: catalog_metadata` and `productIdentity: null`. These are not SAM detections, stable identified products, or proof that a visible object matches a catalog product. The current Chief Editor input receives exact-version Muse visual observations and owner factual sources, not SAM boxes or masks. No Production SAM job/result count was available in this read-only source audit, so actual Production execution and persisted genuine masks are **unverified**.

After separate approval, the smallest safe object path is: operator-selected exact active version and bounded concept; genuine SAM response; verify image hash, dimensions, model origin, consent and permissions; human review of region and any product identity; persist a version-scoped region with provenance; publish only reviewed, display-approved object detail. A box locates an appearance, not product identity. The Chief Editor may receive a region only when it can be joined to the same-version approved observation and same-asset owner source; otherwise it should write ordinary asset-level editorial. Revocation or version change must invalidate the object link.

For Muse Code, future object selection needs a version-scoped region ID, normalized box, provenance/uncertainty, approved detail reference and revocation behavior. Touch/keyboard selection and image-fit coordinate mapping need to use the existing Reader interaction model. No Silver Field frontend change is included here. This object path is post-Hackathon unless a reviewed, persisted SAM capture and frontend contract are separately approved. V2.1 prompt/review improvement is Hackathon-ready for controlled testing after normal review.

SAM cost is one reserved unit per Decoder request, or two with optional Muse commentary, subject to existing limits; provider pricing/quota remains unverified. V2.1 adds no model calls. Deployment requires the usual backend build and approval; `SAM_DECODER_ENABLED` stays false and no Production setting changes are part of this PR. Rollback is a code revert while retaining the existing V2 flag and prior knowledge version; no migration is required.
