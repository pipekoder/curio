# Read & Explore route and editorial review

The current application previously kept the five-stage Reader only in React memory at `/`. The configured Worker in `wrangler.jsonc` serves Vite static assets with `not_found_handling: "single-page-application"`; `/api` remains routed through the Hono Worker. The repository's release runbook records a `workers.dev` origin, but no custom public hostname is configured in version-controlled deployment settings. This change uses relative `/explore` navigation and leaves the actual public hostname to deployment configuration. It does not change Worker bindings, AI flags, D1, or production routing.

After a validated edition is composed, the application opens same-origin `/explore`. A bounded session snapshot stores the validated plan, non-text ranking settings, source label, and retrieval label for up to six hours. It does not store the original prompt or consent choice. Direct visits or reloads revalidate the plan against the current local catalog and any freshly loaded D1 publications before rendering. If the snapshot is missing, expired, malformed, or no longer publishable, `/explore` shows an empty state with a route back to Discover. This process does not repeat the Muse request. The selected edition page is encoded as `?page=N`, while `/explore` stays the primary entry. Browser Back/Forward uses the History API.

The existing interactive opening remains the first Reader view. A deterministic sequence of approved edition features follows below it, alternating image and text spreads. Headlines, descriptions, discovery questions, and connections come exclusively from the already validated plan and catalog; the Reader adds no new inferred claims. The existing authored hotspot, validated SAM display path, contextual stories, and Collect controls remain in place. Motion is short and scroll-triggered only when an image enters view; reduced-motion users see no entrance animation.

[Codapress](https://codapress.co.uk/) was inspected through its live HTML surface. The page exposes a large opening headline, editorial category groupings, book/detail links, article links, and a visible `DRAG` label. Browser access from this development environment received HTTP 403 from its network proxy, so exact spatial layout, hover, scroll animation, drag behavior, and responsive visuals could **not** be verified. No unverified Codapress motion or branding was reproduced. Curio's own approved photographic language and existing Reader interaction system govern this implementation.

Browser evidence and screenshots are in [the review folder](review/read-explore/README.md). The public domain and a real Cloudflare deep-link smoke test remain release checks; no deployment was performed here.
