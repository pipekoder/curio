# Standard Mode 100-unit daily cap — release preparation

This change allows `INFERENCE_DAILY_MAX_UNITS` from 1 to 100 in Standard Mode, defaulting to 20 when absent. Both `/reserve` and the authenticated operator `/status` use the same validated ceiling/daily pair. `wrangler.jsonc` records the owner-approved target of `MAGAZINE_MAX_CALLS=100` and `INFERENCE_DAILY_MAX_UNITS=100`; no AI activation flags are changed. Demo Mode retains its separate 160/day, 500 lifetime policy.

The existing `INFERENCE_BUDGET` Durable Object and `magazine-v1` name are unchanged. Its SQLite `lifetime` counter and current UTC-day counter continue accumulating; no reset, migration, refund or replacement occurs. If Production currently has 17 lifetime units used, raising the ceiling from 20 to 100 reports 83 remaining **only if no new reservations occurred**. The daily status reports its actual retained usage against 100; a UTC-day reset does not reset lifetime usage. Hourly IP caps, rolling cooldown, tester leases, atomic reservations and `sam-once:<assetId>` lifetime keys are unchanged.

Before any separately approved merge/deploy, compare the active Cloudflare settings and bindings to this source config. The Git deployment may overwrite dashboard-only variables, including existing AI flags; retain their approved effective values through the established configuration-safe release process and read them back immediately afterward. Keep `SAM_DECODER_ENABLED=false` and do not make a SAM request as part of verification. Confirm the active Worker version and D1/R2/DO bindings. From unlocked Media Studio, call `GET /api/operator/catalog/intelligence/budget/status` with the existing operator session and verify `mode: standard`, `lifetime.total: 100`, `day.total: 100`, actual used/remaining values, and unchanged reset periods. The status GET makes no reservation. Review Meta account quota and spending controls before separately authorizing paid tests.

Rollback: restore the earlier approved cap configuration and deploy it through the same path; do not delete the Durable Object or counters. If already-used units exceed the restored cap, new reservations fail closed until a separately approved higher cap is reinstated. For immediate inference shutoff, use the existing AI feature flags. No D1 migration is required.
