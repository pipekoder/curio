# PR #30 approved-image demo catalog

`src/editorial-demo-media.ts` records exactly the 26 owner-approved local image files from `DISCOVER_ASSET_ALLOCATION.json`. Every entry has a stable source ID (`curio-owner-NN`), exact asset version (`curio-owner-NN-v1`), story ID, SHA-256 fingerprint, original stage assignment, image path, category, aesthetic tags, authored visual description and explicit related-story IDs. The manifest's dimensions and fingerprint remain authoritative. Image bytes are not copied or modified by this metadata change.

The five Read & Explore images are the only media in this set promoted to **frontend-only** `CatalogItem` records. These records use the existing catalog schema, explicit local display evidence and `isPublishable` checks. Their display permission derives from the owner's approved editorial asset allocation; **AI image analysis and editing remain pending**. They are not added to the Worker catalog, D1, the public catalog API or a verified merchant registry. The other 21 images remain stage imagery with story metadata, not independent sale offers.

Only Read-stage images with a visible object receive a fictional product: chair images `08` and `16`, and the portrait's loose garment `18`. Hotspots are manually authored against source pixels: `08` at (0.50, 0.63) on the chair seat, `16` at (0.48, 0.66) on the chair seat, and `18` at (0.53, 0.62) on the visible garment. The points are approximate interactive anchors, not segmentation masks, verified identities or SAM output. The other 23 images have story metadata only and no invented product hotspot. Prices are fictional USD demo amounts, never stock, checkout or merchant verification. The only brand ID, `curio-fictional-studio`, is explicitly fictional.

The Reader now shows the **first selected validated feature** as its primary image, headline and narrative. Edition page buttons switch to other selected features. A returned Meta plan is validated through the existing schema and asset permission checks, then displayed without altering its selection. Its original illustrated catalog assets stay illustrated; no unrelated photograph is presented as the named product. The authored fallback can select the five separately approved Read photos, with the original six illustrations retained for themes without a matching photo. If the Worker returns a deterministic fictional fallback while live AI is disabled, the frontend composes the local approved-photo fallback after validating that response; a D1 edition is never replaced. The UI always discloses authored fallback versus validated Meta output.

Related asset IDs are authored demo connections, not asserted common designers, sources or materials. Future Media Bank substitution can use the stable asset/story/product IDs and version fingerprints; new bytes or permissions require new review. No upload or migration is part of this PR.
