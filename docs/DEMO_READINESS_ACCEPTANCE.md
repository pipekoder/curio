# Demo acceptance and editorial quality

Based on main after PR #25 (`d5eab42`). This is functional acceptance and editorial
quality work; there are no component, CSS, layout or visual redesign changes.

## Reproduce the approved-content demo

```sh
npm ci
npm run build
npm run test:browser -- tests/demo-readiness.spec.ts
```

The new test runs at 1440 px desktop and 390 px touch/mobile (reduced motion on
mobile). It blocks all external network requests, intercepts the editorial endpoint
as disabled, uses only approved `/catalog/*.svg` illustrations and emits JSON plus
magazine/story/collection screenshots into `test-results/`. There are no live
model calls and no dependency on a new gallery or production D1.

For a manual local rehearsal, run `npm run dev`, keep Meta consent unchecked and
follow this checklist. The test harness supplies the disabled-API/loading scenario;
manual Vite also falls back locally when its API is unavailable.

- [x] Initial Tab reaches the visible skip link; Enter focuses the prompt.
- [x] Submit “Focus on Scandinavian reading rooms and paper lamps”. Pending
  generation disables the prompt and submission control; API failure yields an
  authored edition, labeled “AI not used”.
- [x] Read the home edition; select the Paper shade hotspot by keyboard (desktop)
  or touch (mobile). The original illustration remains visible and the reveal is
  accessible. Mobile reduced motion removes its animation.
- [x] Open the connected story, verify focus moves to its heading, and follow a
  related discovery. Existing regression tests also check source citations.
- [x] Collect the related story, close the dialog, reload and reopen the collection.
  The same story can be revisited through “Continue exploring”.
- [x] Refine with “Surprise me with woodland paths and lakeside travel”. The
  leading asset changes from Paper Moon Lamp to Moss Path, and composition from
  `hero` to `layered`. The magazine remains the primary experience.
- [x] No horizontal document overflow, external media requests, Meta consent,
  paid inference or third-party image publication occurs in this rehearsal.

The broader suites retain coverage for consent, caching, shared inference budgets,
D1 rights/revocation, missing assets, unavailable storage, delayed startup, story
navigation, synthetic SAM geometry/grouping and publication/Collect rehydration.
Screenshots are local test evidence, not a review of a new production deployment.

## Editorial quality changes

The single Muse editorial request now asks for a clear central idea, distinct
concrete details per feature, a deck explaining what to notice, coherent comparative
connections and a different grounded curiosity question for each feature. It does
not request executable code, image pixels, new citations or new factual claims.
There are no added model calls or automatic retries.

The V2 evaluator additionally rejects:

- Generic adjective piles in feature headlines as well as the magazine title.
- Repeated meaningful words, case/punctuation-normalized duplicate headlines or
  narratives, and near-identical narrative content despite reordered wording.
- Reused discovery questions and atmospheric connections without a concrete
  comparison.
- Unqualified claims that a composition creates psychological outcomes such as
  calm; interpretation must remain explicitly tentative.

Existing strict vocabulary, observation-key/subject/material grounding, material
uncertainty, exact asset pairs, approved media, sequencing and schema checks remain.
A versioned quality policy is included in the existing cache key so older prompt
results cannot silently bypass the updated policy. Cache validation and inference
accounting remain in the existing planner.

Fixtures include positive grounded copy, unsupported identity/material/subject
claims, irrelevant discovery, repetitive copy and generic language. The sanitized
successful legacy Focused Home capture remains valid under its original contract.
Legacy compatibility is deliberately retained; these stricter style checks target
`qualityVersion:2`, not a retrospective reinterpretation of earlier live evidence.
The revised positive V2 fixture is authored test copy, **not new live Muse output**.

## Model evidence and remaining blockers

- The earlier genuine Muse/SAM tests remain historical evidence. They were not
  rerun, and the seven genuine SAM regions are not recreated or fabricated here.
- Automated Muse generation/analysis and SAM responses are mocked or recorded.
  Demo hotspots on the six illustrations are authored annotations, not genuine
  segmentation. Labels preserve this distinction.
- No new live Muse response has validated the revised prompt's writing quality.
  Automated heuristics cannot prove literary quality or every semantic claim;
  a human editorial review remains necessary before a separately authorized live
  acceptance. Closed vocabulary is intentionally limited in expressive range.
- The owner gallery has not been received or authorized. The earlier six-source
  image harvest remains blocked by egress/DNS-pinning compatibility; zero such
  external images are published. The demo works without them. Use the separate
  [owner gallery intake runbook](OWNER_GALLERY_INTAKE.md) when content is supplied.
- Arbitrary external-gallery SAM images still need a separately reviewed exact
  permit/transport adapter. Publication never authorizes analysis or editing.
- Production flags, D1 and deployment have not been changed or independently
  revalidated by this local acceptance. There is no live browser-engine coverage
  beyond Chromium here; Safari/Firefox and physical-device checks remain manual.
