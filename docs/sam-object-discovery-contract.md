# Reviewed SAM object discovery MVP

This backend change is default-off: it does not enable `SAM_DECODER_ENABLED` or run Meta. Migration `0005_sam_object_reviews.sql` must be applied **before** deploying code that enables live Decoder capture. No Production migration or flag change is included in this PR.

The existing authenticated, consented `POST /api/decoder` remains the only inference route. For an eligible private R2 version it now checks for a matching persisted capture first. A cache hit returns the existing segmentation with `reused: true` and consumes no new model reservation. A new successful SAM response is persisted as `sam_detection` with the exact image SHA-256, dimensions, model, concept and normalized boxes; its regions start `pending`. The response adds `captureId` and `reused`, preserving `segmentation` and `commentary`. Failed inference is never retried automatically. The server cannot infer product identity from a box.

The existing catalog-operator authentication protects `PATCH /api/operator/catalog/object-regions/:captureId/review`. JSON: `{ "regionId": "sam-1", "expectedRevision": 0, "status": "approved", "editorialDetail": "A short human-reviewed observation.", "productId": null, "identityEvidence": null }`. Use `status: "blocked"` to revoke. A product ID is accepted only if linked to the exact media version and accompanied by operator-supplied identity evidence. The reviewer must verify that the region actually shows the linked product; a Media Studio association alone is insufficient. Review records are distinct from raw model output and have optimistic revision checks.

`GET /api/catalog/object-regions/:versionId` is public and read-only when `CATALOG_PUBLIC_ENABLED=true`. It returns HTTP 404 if the exact version is no longer an eligible publication. On success: `{catalogId, assetId, width, height, regions:[{id, box:{x,y,width,height}, label, editorialDetail, product:null|{id,name,kind:"owner_mockup"}, provenance:{origin:"sam_detection",model:"sam-3.1",uncertainty:"model_estimate_not_identity",reviewed:true}, confidence}]}`. `assetId` is the exact `version-...` ID; `id` is capture-scoped and stable. Empty `regions` is valid and means nothing approved for display. This route rechecks active version, publication, display/analysis grants, review status, image fingerprint and current product relationship. It never returns pending/blocked captures, private evidence or unapproved observations. Media 404 or missing publication must remove the corresponding frontend selection.

For Muse Code: request regions only for the currently displayed exact `assetId`; render a region on the image using normalized coordinates after applying the actual contain/cover fit transform. Do not stretch boxes by viewport dimensions alone. A click/touch/keyboard selection may open a compact editorial detail window; label `owner_mockup` products as fictional. On version change, route error, media 404 or returning to the exhibit, clear stale selection and refetch. Avoid treating a model box as a verified mask or product identity. Masks are not in this MVP response. Do not add decorative hotspots for images with an empty result.

The six pilot images have **zero claimed SAM captures in this PR**. The 1–2 object target per image depends on separately authorized paid SAM calls and human review; no synthetic regions are inserted to meet that target. Current Editor input remains asset-level; object-aware prose and Silver Field UI require separate approval. Each new uncached Decoder request reserves one inference unit, or two when optional Muse commentary is enabled, subject to existing limits. Rollback is `SAM_DECODER_ENABLED=false`; public approved-region reads may be withheld with `CATALOG_PUBLIC_ENABLED=false`, but that also affects the catalog, so prefer blocking the review rows or reverting this route if only objects must be hidden.
