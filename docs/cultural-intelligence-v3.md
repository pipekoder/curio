# Cultural Intelligence V3 — default-off research foundation

## Assessment and reused boundaries

Latest base is `main` with #68, #69, #71 and #74. V3 reuses the published D1 catalog, exact-version owner facts and Muse visual observations, the Chief Editor → independent Reviewer → bounded Revision → Confirmation flow, the shared `magazine-v1` budget Durable Object, and #71's draft-only long-form source interface. It does not change Silver Field, the public Editorial request schema, the four-unit short-form reservation, or the long-form job lease/state machine.

Draft #70 contributed the allowlisted HTTPS, no-redirect, bounded-text retrieval pattern. V3 adds passage IDs, document fingerprints, a structured Muse research planner, claim-to-passage and relationship contracts, an operator review boundary, private R2 evidence packs, and optional use of reviewed claims as exact-version Editorial sources. #70 is not merged. Meta Muse Spark 1.3 chat completion is the only verified AI capability in this repository. No verified Muse embedding or web-search endpoint exists; retrieval is lexical-only. An embedding provider is **not configured**. No graph database or D1 migration is needed for the bounded pack model.

## Trust and data flow

`POST /api/operator/catalog/cultural/plan` requires existing catalog-operator Bearer authorization, same-origin protection, explicit consent, `CULTURAL_INTELLIGENCE_V3_ENABLED=true`, valid Muse configuration, and a successful **one-unit atomic reservation** in the existing Durable Object before one bounded planner call. No retry is made. A planner question or relationship is a hypothesis, never evidence. This operator preparation call is separate from the existing four-unit public Editorial workflow. The current standard per-IP cooldown applies; operators should not chain calls expecting a cooldown exemption.

`POST /api/operator/catalog/cultural/retrieve` accepts 1–3 operator-selected URLs from `RESEARCH_SOURCE_ORIGINS`. It makes at most three 10-second, 128-KiB HTTPS text requests, rejects redirects and unsafe/unallowlisted URLs, deduplicates by content hash, and returns lexical relevance, an optional operator-assigned source-quality component, bounded passage offsets, stable IDs, fingerprints, retrieval times, and `pending` verification/rights. It stores a private R2 fingerprint proof for each captured passage, never the full fetched page. It does not search the web for URLs. Tracking query parameters are removed during canonicalization. No semantic rank is claimed without a verified embedding provider. It does not prove source authority, factual accuracy, ownership, or quotation rights. A cached passage can be stale; operator review must check the original source and freshness before approval. HTML extraction is intentionally basic and unsuitable for complex sites.

An operator can submit a reviewed evidence pack to `POST /api/operator/catalog/cultural/packs`. The route rechecks current public publication for each exact asset version, validates bounded identities, source/passage fingerprints against those captured R2 proofs, claim references, source rights status, review status and relationship references, then stores the pack privately in existing R2. The operator's `approved` status records a human editorial decision; the model cannot set it via the planner or retrieval route. The operator must verify source authority, claim support, conflicts, quotation rights and image relevance before submission. The code cannot independently prove that a cited passage is true or legally reusable. Use paraphrase-approved evidence; quoted text needs separate rights approval.

With `CULTURAL_INTELLIGENCE_V3_ENABLED=false` (the committed default), Editorial V2.1 is unchanged. When enabled, `/api/editorial` only reads a private, precomputed pack whose exact set of asset-version IDs matches the current publication-filtered pool. It makes **no live web requests and no additional Muse call**. Invalid, absent, stale-version or revoked packs fail closed to the existing V2.1 workflow. Approved cultural claims become `cultural_claim` Editorial sources with same-asset IDs; the Chief Editor, independent Reviewer, Revision Editor and Confirmation review receive the same source set. The normal source-ID validation, publication checks, Reviewer hard-failure behavior, fallback and cache revalidation still apply. Pack content participates in the generation cache key. R2 pack key derivation is stable and private; revocation removes it from the eligible editorial pool, and approval is revalidated at read time.

The long-form adapter `culturalSourcesForLongform` converts only operator-approved, cited factual claims into #71's existing `cultural_research` source shape. It does not start a long-form job, change its 18-step bound or allow publication. Future long-form inference must reserve each paid step before invoking its model adapter; #71 currently has no live production inference policy.

## Sufficiency, performance and operational bounds

The planner returns at most three research questions or explicitly stops/narrows. `assessCulturalSufficiency` can stop, request one further retrieval round, or narrow; an orchestrator must cap any further round. No autonomous browser loop is wired into visitor requests. Retrieval is lexical-only and requires preselected allowlisted URLs. The default Editorial path pays zero extra V3 units; a preparation planner uses one unit and up to 700 completion tokens with a 12-second timeout. Its cost and Meta quota still require provider readback. The existing four-unit Editor/Reviewer/Revision/Confirmation reservation remains unchanged. The existing 100-unit Standard daily/lifetime caps are shared, not extended by V3. No Production flag or source origins are configured by this PR.

## Evaluation and rollout

Automated fixtures cover exact-version binding, passage references, rights and conflict rejection, SSRF controls, lexical retrieval, planner reservation and sufficiency behavior. These are **mocked** checks, not evidence of improved Muse prose. The V2.1 baseline can be evaluated with the same approved assets and prompts only after a separate paid-test authorization. Human evaluation should score factual support/citation accuracy, connection relevance, originality/depth, hallucinations, source diversity, latency and units for: Japanese interiors, Scandinavian functionalism, jewelry craft, cultural-heritage travel, indirect cross-disciplinary topics, adversarial pages, conflicting evidence, and provider unavailability. Preserve the actual model outputs and judge blind pairs; do not infer quality from the presence of citations.

Before any activation, review an allowlist of authoritative HTTPS origins and the exact reviewed packs; verify provider quotas, shared budget headroom, current D1/R2 permissions, and a controlled fallback test. Deploy through the existing Git path with the flag still false. Configure `RESEARCH_SOURCE_ORIGINS` only for the operator research endpoint. A separate owner approval is required to enable V3 and run any paid Muse call. Rollback is `CULTURAL_INTELLIGENCE_V3_ENABLED=false`; it does not delete R2 packs or alter budget history. The deployment must read back all AI flags because source-controlled Wrangler values may replace Dashboard overrides.

## Remaining limits

This PR does not provide semantic embeddings, automatic URL discovery, a live public research loop, independent automated source-authority verification, or a fully automated V2.1-versus-V3 writing-quality result. The current Editorial schema can carry exact cultural source IDs, but it does not expose claim-level citation spans in public narrative text. The independent Reviewer assesses semantic support; the technical gate proves identity and permissions, not semantic truth. These limits should be resolved before claiming a complete autonomous cultural research engine or measurable editorial improvement.
