# Silver Field backend integration contract

Scope: the product frontend at `/`. `/legacy` is not an integration target. This contract describes the existing Worker at `main` commit `49aeda562b650b1153afac14c1a772e36bd30ec8` plus the focused backend fixes in this branch. It does not authorize inference or publication.

## Existing requests and responses

`POST /api/editorial` accepts JSON `{ "prompt": "...", "consent": false }` with a nonempty prompt of at most 1,000 readable characters. It also accepts the existing strict preference-shaped request. The request must come from `PUBLIC_APP_ORIGIN` with `Content-Type: application/json`; the body is limited to 4 KiB. Consent is required before any Meta call. The frontend must send the reader's actual choice, rather than assuming consent. `MAGAZINE_AI_ENABLED=false` produces a deterministic response without inference.

A successful HTTP 200 response contains:

| Field | Meaning |
| --- | --- |
| `plan` | Validated `EditorialPlan`: title, deck, one to six features, optional connections. Each feature has exact `catalogId` and `assetId`, prose, theme, layout and motion. Quality-version 3 features also cite exact `sourceIds` and may cite observation keys. |
| `items` | The eligible catalog records used to build the plan. Join a feature to an item only when **both** `item.id === feature.catalogId` and `item.image.id === feature.assetId`. `item.image.id` is the exact D1 version ID for uploaded content. The item includes the image URL, dimensions, alt text, attribution, provenance and independent permissions. Do not substitute a static manifest item for a D1 feature. |
| `source` | `meta` means a validated model result (including a cached one); `deterministic` means a server-authored fallback. |
| `retrieval` | `d1` means a D1-derived pool; `fictional` means the authored demo pool. This is independent of `source`: `deterministic` + `d1` is possible. |
| `cached` | Whether a previously validated model plan was served from the Worker's short-lived cache. A cache hit still rechecks current publication eligibility. |
| `inference` | `{attempted, reservedUnits, latencyMs, usage}`. `usage`, when present, contains input/output/total token counts and possibly cached-input tokens. A cached response has `attempted:false` for this request even when `source:meta`. |
| `fallbackReason` | Present on deterministic fallback; examples include `disabled`, `consent_missing`, `pilot_allowlist`, `pilot_not_ready`, `pilot_authorization`, `configuration`, `analysis_permissions`, `budget`, `invalid_output`, and `editorial_rejected`. Treat as a reason code, not raw model evidence. |
| `editorialSources` | Bounded owner-supplied mockup source records keyed by exact asset version. These are source attribution, not independently verified brand facts. |
| `imageContextAssetIds` | Present on successful model/cached responses when exact-version Muse image observations informed the plan. Absence does not imply that SAM ran. |
| `validationDiagnostic` | Optional bounded code/field on validation failure; no raw model output. |

The response is `Cache-Control: no-store`. A 400/403/503 or network timeout must be represented as a failed request with a disclosed authored fallback if the frontend chooses to stage one. The backend does not stream progress or return progress percentages.

### Reproducible, non-billable fixtures

- `tests/fixtures/silver-field-api.ts` provides an authored request and fully schema-validated deterministic response built from Curio's approved local demo catalog. `tests/silver-field-api-contract.test.ts` verifies IDs and shape.
- `tests/media-studio.test.ts` creates an owner-mockup PNG in local Miniflare D1/R2, supplies fictional owner metadata, uses a mocked Muse analysis response, then checks `GET /api/catalog/published`, `POST /api/editorial` (AI disabled), and `GET /api/media/:version`. The test asserts the same exact version ID and media URL across endpoints. These IDs are generated by the local fixture; they are not production IDs or evidence of a live Muse call.

## Publication and media

`GET /api/catalog/published?ids=version-<64 lowercase hex>` returns `{items, nextCursor}`. Without `ids`, the endpoint returns up to 50 eligible items per page; pass the returned cursor for the next page. It is available only with `CATALOG_PUBLIC_ENABLED=true` and D1 binding. The public listing rechecks the active asset version, current linked content, display reviews, exact URL, attribution, and evidence. Publication alone does **not** establish editorial readiness or AI-analysis rights. Content Studio items need a linked product and brand with the required descriptions before D1 editorial retrieval; live pilot inference additionally needs the six-version allowlist, exact-version observations, consent, configuration, operator authorization when Reviewer is enabled, and inference budget.

The primary image can be `item.image.path` (authored local asset) or `item.image.externalUrl` (published external or private-R2-backed URL). Owner Content Studio uploads use `${PUBLIC_APP_ORIGIN}/api/media/${versionId}`. `GET /api/media/:version` reads private R2 and now applies the same current-publication check as the public catalog. It returns 404 after display/content revocation. Media URLs must be treated as version-specific; a new image version never inherits a previous version's approval. The public catalog item has `provenance.attribution` and `image.alt`; do not use filenames or AI observations as verified identity.

## Journey without a new endpoint

For an MVP browsing list, `/api/catalog/published` is sufficient. Map each eligible item to a frontend node using `item.image.id` as stable node/asset ID, a bounded label from `item.name`, and an approved image URL. Page through `nextCursor`; do not expose operator records. The current frontend node schema accepts only same-origin thumbnail **paths**, while R2 items return same-origin absolute URLs. Muse Code can validate the origin and convert a verified `/api/media/:version` URL to its pathname in its adapter. Arbitrary external URLs cannot be converted into same-origin paths. The existing catalog response does not supply cross-asset `edgeHints`; leave those absent unless a relationship is backed by a real plan connection or a verified catalog link. Thus this endpoint supports browsing, but not a complete dynamic relationship graph. No new endpoint is essential for the first published-media promenade.

## Clear, privacy and retention

Silver Field keeps the current prompt and exhibits in React memory and writes `curio.spatial.session.v1` to browser session storage on submit. Clear removes that key, the old `curio.explore.edition.v1` session key, and the old `curio.collection.v1` local-storage key; it resets in-memory state. It intentionally retains the Content Studio operator token (`curio.media.operator`). It does not send a deletion request to the Worker. The Worker stores catalog/media, publication and owner-supplied import text in D1/R2 independently of visitor Clear. Editorial plans live in a bounded isolate-local map for five minutes, keyed by a digest of preferences and current eligible content; each hit is revalidated against current permissions. The code does not persist the raw public prompt to D1, but it sends the prompt to Meta **only after consent and other gates pass**. Cloudflare observability is enabled in `wrangler.jsonc`; actual platform log/analytics retention and any externally retained model requests require account/provider settings review. Clear must not claim to erase those server or provider records.

## Frontend handoff and acceptance

Muse Code owns the spatial adapter and rendering. It should use returned `items`, validate both IDs and current display eligibility, render the approved media with attribution, and distinguish `source` from `retrieval`. It should preserve the visible `AI not used` disclosure for fallback. It must obtain consent before sending `consent:true`; no UI or API should infer consent from a prompt. Loading is the real pending request; no fake progress. If WebGL is unavailable, the current spatial code falls through to `PublicApp` (the old 2D experience); replacing that with an in-scope accessible fallback belongs to Muse Code and is not changed here.

Acceptance should cover: one locally uploaded, fully described, approved item reaching D1 retrieval and `/api/editorial`, exact-ID staging and `/api/media` display, Journey browsing, publication revocation returning no public bytes, deterministic fallback with inference disabled, consent-off behavior, timeout, Clear after reload, and no production records or paid inference used in automated tests. Production configuration and real record eligibility must be verified separately before claiming live integration.
