# Long-form Editorial backend foundation

This is a private, default-inaccessible foundation for a future 1,500–4,000-word article pipeline. It does **not** change `POST /api/editorial`, the Silver Field Reader, consent, existing inference budgets or Production flags. No route or real model adapter is wired to it, so it cannot trigger paid inference in its current form. Its D1 table is a private resumable job store, not a published article table.

`LongformJobStore.create` accepts a prompt, voice, knowledge version and 4–24 already verified, rights-approved evidence records with stable IDs and digests. The input hash is the cache identity. `advanceLongform` executes at most one model call per invocation through an injected adapter and an explicit reservation callback, then checkpoints the result. Its lease and revision checks prevent concurrent advancement; a failed call marks the job failed and does not retry automatically. Four outline sections each require cited source IDs and 375–1,000 words. Section drafts receive independent review and at most one targeted revision/review cycle. Whole-article review must pass without a factual hard failure before a 1,500–4,000-word draft is marked complete. The ceiling is 18 model calls per job. This foundation does not publish an article, and a complete state is not permission to show it publicly.

Before a live adapter or endpoint is approved, engineering must: map each model step to existing Muse and independent Reviewer instructions; reserve up to 18 calls under an explicitly approved budget policy; confirm provider token/context and timeout limits for 1,000-word sections and a 4,000-word whole-article review; establish exact source-to-claim citations and quotation rights; add operator review and publication permissions; define stale-source invalidation and partial-failure recovery after a provider success but checkpoint failure; and decide a background execution mechanism for the worst-case multi-step runtime. The existing 2,200-output-token/15-second calls and four-unit short-form reservation cannot simply be reused for the entire article. No new frontend or Production activation is part of this PR.

Migration `0006_longform_jobs.sql` is intentionally ordered after the SAM review migration `0005`; this PR is stacked on the SAM branch. Neither migration has been applied to Production. The approved short-form flow remains the Hackathon path; this long-form foundation is a post-Hackathon backend increment until the above safeguards and a Reader design receive separate approval.
