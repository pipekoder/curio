# Demo Testing window

`DEMO_TESTING_MODE=true` activates a separate short-window allowance only for a valid, IP-bound, HttpOnly Demo Tester session. It also requires the existing Demo policy: `EDITORIAL_DEMO_BUDGET_ENABLED=true`, `EDITORIAL_DEMO_DAILY_UNITS` (up to 160), `EDITORIAL_DEMO_LIFETIME_UNITS` (up to 500), the existing public/editorial/review AI flags, `INFERENCE_BUDGET`, and the existing operator or tester credentials. The master toggle defaults to off; `false` and unset keep the prior Demo and standard rate policies. Invalid toggle or window values reject reservations rather than granting an allowance.

| Variable | Default | Valid range |
| --- | ---: | ---: |
| `DEMO_TESTING_MODE` | `false` | `true` or `false` |
| `DEMO_TESTING_WINDOW_SECONDS` | `900` | integer 300–3600 |
| `DEMO_TESTING_WINDOW_UNITS` | `12` | multiple of four, 4–24 |

The window is a fixed UTC interval: `floor(now / windowSeconds)`. Three accepted four-unit reviewed generations fit in a fresh default window. At the boundary, only that window's counter expires. Accepted reservations, including failed or timed-out provider calls, remain charged to the shared daily and lifetime counters. A renewed window does not clear tester daily use, reservations, SAM once-per-asset use, or provider billing. Changing the window duration can start a different short-window key, but cannot reset the shared daily/lifetime limits.

The reservation order is SAM once-per-asset (when applicable), shared lifetime, shared UTC day, then the caller's rate policy. A valid tester using the toggle is subject to the existing two-lease concurrency cap, existing tester UTC-day limit, and the dedicated window. Their ordinary per-IP hour, tester hour, and cooldown do not also block the enhanced window. With the toggle off, the existing tester hour/day, per-IP hour/cooldown, pilot, and anonymous limits remain. SAM and Article Preparation keep their existing one-unit, once-per-asset and preparation-specific limits; neither gets the testing window. The tester daily default is 120 units and can be changed within its existing validated 4–160 range with `INFERENCE_TESTER_DAILY_UNITS`. The shared Demo daily and lifetime caps remain separately configured and authoritative.

The existing authenticated `GET /api/operator/catalog/intelligence/budget/status` reports `demoTesting.enabled`, `authenticated`, `active`, the configured window and, for an authenticated session, `demoTestingWindow` use, remaining units, UTC reset, whether another four-unit reservation is allowed, and the first blocking limit. It also retains shared quota totals and recent denial categories. To inspect a tester's window, the operator must have both valid operator authorization and that tester session in the same request; status never exposes a tester key or another visitor's window.

For a controlled activation, deploy this code through the existing release process with no toggle enabled, confirm the existing shared Durable Object and Demo caps through the protected status endpoint, then set the three variables in the Worker environment. Establish an existing Demo Tester session and read status again before testing. Dashboard-managed variable changes affect the effective Worker environment without a source change, but Cloudflare publishes a new Worker version for a settings update; a later Git/Wrangler deployment may replace Dashboard values with `wrangler.jsonc` values. Record the intended values in the existing configuration process and read them back after each deployment. No Durable Object replacement, counter reset, or D1 migration is needed.

To turn off the enhanced window, set `DEMO_TESTING_MODE=false` and verify `demoTesting.active=false` in the protected status endpoint. For emergency AI shutoff, use the existing `MAGAZINE_AI_ENABLED=false` control. All usage history remains in `magazine-v1`. The existing global caps or an external Meta quota can still deny an otherwise available window.
